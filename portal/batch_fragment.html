測量範圍與保護措施

  • Complexity 分類耗時直接取自該次 eval 回應的 metrics.complexity.execution_time_ms，包含 complexity classifier 內部工作，不是純 AMX 指令或 embedding kernel 計時。
  • SR-only HTTP 耗時從 Portal 發出 eval 到讀完回應，以 monotonic clock 計量，不含 JSON 解析；包含網路與 SR 處理，但不含 LiteLLM／GPU。與單題頁的 trace 路由區間是不同指標。
  • 使用原題庫 16 題暖機，各側一次；暖機結束後，正式每輪完整 100 題。同輪兩側題序相同，逐題交替先後，下一輪反轉起始側；題序 seed 與實際順序保留於 JSON。
  • 一次只跑一個批次，且批次期間阻止新的單題比較請求；這不阻擋原本聊天或其他叢集工作，不構成主機隔離。沒有重建 Pod、切換 AMX 或調整 CPU 配置。
  • 暖機任一筆失敗即停止；正式連續三筆失敗即停止。其餘失敗保留，不自動重試；沒有資料、HTTP 失敗、缺少有效計時均不填成 0 秒。
  • 停止會在目前一筆結束後停止排程；socket timeout 10 秒，整批經過 20 分鐘後不再排程新請求。頁面未回報心跳超過 45 秒也會停止排程，請保持頁面開啟。瀏覽器背景節流可能導致此安全停止；不保證中止 SR 內已執行的工作。
  • 資料暫存在 Portal 記憶體，保留最多一小時；Portal 重啟可能遺失。頁面刷新會嘗試接回同一 run，不會自動重跑；請下載 JSON／CSV 保存正式記錄。部分結果可下載但不冒充完整批次。
