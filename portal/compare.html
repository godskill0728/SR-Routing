如何解讀這個 demo

  • SR 路由階段＝同一 trace 中，signal.evaluation 開始到 upstream.request 開始的區間；含訊號評估、決策與其間處理，不含更早的接收處理，也不是完整 ext_proc 路由 histogram。
  • 訊號評估＝signal.evaluation span duration，包含分類等訊號處理。現行 trace 沒有独立的純 complexity／embedding 計時，因此不另外捏造該秒數。
  • 首段文字／完整回應從瀏覽器送出開始計時，包含網路、Portal、SR、LiteLLM、GPU 排隊與生成。首段文字可能是 reasoning，不是純 GPU TTFT。
  • Trace 可能稍後才入庫；自動查詢最多約 60 秒，未取得會顯示不可用，不代表 0 秒。查詢 trace 不會重送 prompt。
  • 兩側使用相同 prompt、參數與 token 上限，但回答長度、路由模型及後端排隊可能不同。若模型不同會提示；單次結果不是 AMX 因果加速倍率，也不是受控效能測試。
  • ON / OFF 是既有服務名稱，並非這筆請求 AMX 指令執行的證明。AMX 影響 CPU embedding，不代表 GPU 生成加速。thinking 關閉是送出的參數，不保證所有後端支援。
  • 每側只送一次，失敗不自動重試；最多接收 120 秒。停止接收或關閉頁面不保證 GPU 端立即停止。達 token 上限可能截斷答案，會標示 finish reason。
